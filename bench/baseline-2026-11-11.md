## ReleaseSmall executable sizes

Sizes are on-disk PE executable bytes from `zig-out/bin`, built using
`zig build -Doptimize=ReleaseSmall <step>`. These are application executables,
not the static library size.

| Target | Build step | Bytes |
| --- | --- | ---: |
| Minimal root import | `example-size-minimal` | 504,320 |
| Gzip only | `example-size-compression` | 529,920 |
| Router-only web framework | `example-size-web` | 551,424 |
| HTML parsing | `example-size-parsing` | 591,872 |
| HTML parsing example | `example-parse-html` | 753,664 |
| Basic HTTP client | `example-size-client` | 1,613,824 |
| HTTP/1.1 client | `example-size-http11` | 1,614,336 |
| HTTP/2 client | `example-size-http2` | 1,614,336 |
| HTTP/3 client | `example-size-http3` | 1,614,336 |
| Basic HTTP server (default protocol configuration, docs not mounted) | `example-size-server` | 2,663,936 |
| Basic HTTP/1.1 server (runtime HTTP/1.1 only, docs not mounted) | `example-size-server-http11` | 2,663,424 |
| Basic HTTP server with all documentation UIs mounted | `example-size-server-docs` | 19,455,488 |
| REST/OpenAPI server example | `example-rest-api` | 19,922,432 |
| Full client/server integration example | `example-full-integration` | 19,908,608 |

The client size targets build a request to loopback port 1; they are compiled
for size measurement and are not run. The server target registers a route and
enters the server loop; it is compiled but not run. The HTTP/1.1, HTTP/2, and
HTTP/3 targets use the same request shape and differ only in the requested
protocol. Size comparisons are specific to this compiler, OS, target, and
link settings.

Compared with the 504,320-byte minimal import, the router-only target adds
47,104 bytes, parsing adds 87,552 bytes, and gzip adds 25,600 bytes. Explicitly
mounting all documentation UIs adds 16,791,552 bytes to the basic server,
primarily from the embedded Swagger UI, ReDoc, Scalar, and GraphiQL assets. The
server no longer imports those assets unless `httpx.docs.mount` is used. The
three protocol-specific client samples remain within 512 bytes of one another
(1,614,336 bytes each for HTTP/1.1, HTTP/2, and HTTP/3), so these samples do
not demonstrate protocol-level binary isolation. Runtime protocol selection
reduces the docs-free server by only 512 bytes; server protocol code isolation
remains an open optimization.

## Test baseline

`zig build test --summary all` passed 1,175/1,175 native tests with zero skips
in Debug, `ReleaseFast`, `ReleaseSafe`, and `ReleaseSmall`. Windows `std.Io`
cannot provide the timed
receive operation concurrently for this socket backend, so

Formatting and checks at baseline: `zig fmt .` and `git diff --check` passed.

## Explicit documentation feature boundary (2026-11-12)

Server configuration no longer imports or mounts documentation UIs. Apps opt
in with `httpx.docs.mount(allocator, &server.router, config, info)` after
registering application routes, then call
`httpx.docs.unmountRouter(&server.router)` before `server.deinit()`. A server
regression test checks `/openapi.json` returns 404 without that mount. Current
Debug, `ReleaseFast`, `ReleaseSafe`, and `ReleaseSmall` suites each pass
1,175/1,175 tests; the full example build passes 201/201 steps. The isolated
ReleaseSmall sizes below were rebuilt from this tree and match the recorded
byte counts. Cross-target compile checks pass for x86_64 Linux, x86_64 macOS,
x86_64 Windows, x86 Linux, AArch64 Linux, ARM Linux, Thumb Linux, and RISC-V
32-bit Linux. These are compile-only checks on this Windows host; target tests
were not executed under QEMU here. The x86 Linux pass uncovered and fixed
32-bit atomic width and HPACK integer-to-offset issues. The Linux UDP timed
receive path also had an unreachable `WouldBlock` case in its inferred error
set; removing it restored the cross-target compile.

## Benchmark harness and additional size targets (2026-11-12)

The microbenchmark bodies now count errors instead of silently returning from
failed work; `zig build bench --summary all` completed with no failed
iterations. It reports median round latency along with min, average, and max.
The latest repeat measured HTTP/1.1 loopback GET at 82.51 us median (11,996
req/s average), pooled h2c GET at 55.57 us median (17,443 req/s average),
HTTP/3 fresh-handshake GET at 202.74 ms median (4 req/s), HTML parsing at
11.86 us median for the small document and 20.90 ms for the ~594 KB document,
and gzip at 16.58 us median compression / 4.79 us median decompression. These
are repeat baseline observations, not demonstrated before/after improvements.

After adding URI/status/method/authority parsing, JSON, authentication,
template, watcher, static-file, SPA, worker-pool, and HTTP/2/3 primitive
workloads, the full harness completed again on 2026-11-12 with no reported
failed iterations. The latest run measured HTTP/1.1 loopback GET at 91.33 us
median (10,865 req/s average), pooled h2c at 60.32 us median (16,053 req/s),
fresh HTTP/3 at 203.19 ms median (4 req/s), full TLS at 3.18 ms median, and
resumed TLS at 2.84 ms median. Timing varies across runs and is not an isolated
before/after comparison.

Added ReleaseSmall feature samples: `example-size-web` (router-only) measured
551,424 bytes and `example-size-parsing` measured 591,872 bytes. The minimal
root import remains 504,320 bytes. Protocol client samples remain essentially
the same size; runtime protocol selection does not yet materially isolate
server protocol code.
